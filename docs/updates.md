# 应用内更新

从 v1.0.0-beta.2 开始，窗口右下角提供「检查更新」。启动 3 秒后后台检查一次，不按设备刷新频率轮询，不自动下载。设置可关闭自动检查或关闭测试版渠道。发现新版后点击「下载并更新」，下载、签名和文件完整性校验通过后，停止本程序的投屏和采集，恢复手机代理，退出并替换，再启动新版。

beta.1 和更早版本需要手动下载 beta.2 完整 ZIP 到一个独立、可写的目录并解压一次。必须保留 AdbDesk.installation.json、运行库和 tools；不要仅替换 EXE，也不要在 ZIP 预览中运行。源码构建目录不允许原地更新。个人设置和采集恢复记录位于用户 LocalAppData，不在替换范围。

手动复制新版时若提示 `tools/scrcpy` 文件夹正在使用，可先完全退出旧版和投屏，再把新版完整解压到新目录运行，避免覆盖占用中的工具。若必须覆盖原目录，应关闭使用 ADB 的工具，再通过任务管理器的“详细信息”确认并结束从旧目录运行的 `adb.exe`／`scrcpy.exe`，然后重试完整复制；结束 ADB 服务会暂时中断其他工具的调试连接。不要跳过 tools 文件，否则可能混用新旧组件。

更新只读取 XieDH312/AdbDesk 的 GitHub Releases。默认接收测试版；关掉后只查正式版，不降级当前版本。GitHub 不可达时当前程序保持可用，可稍后重试。Windows 智能应用控制仍可能拦截未签名程序：更新清单签名用于应用自身验证，不等于 Windows 代码签名，不能绕过系统策略。

## 发布新版

从 beta.4 开始使用 Android 风格的两个版本字段：csproj 的 `Version` 作为 versionName 展示，`VersionCode` 为正整数，每次发布必须递增（beta.10 为 10010）。新版按远端 code > 本地 code 判断更新。为兼容已发布的 beta.2/beta.3，版本名称及标签仍使用递增 SemVer，原 schema1 清单与签名公钥保持不变。

新增 `AdbDesk.version.json` 同时存在于程序目录、ZIP 和 Release 附件中，包含 versionCode/versionName。它的原始文件摘要受签名清单保护，不能只改附件数字冒充新版。新版不通过旧版只有名称的清单进行降级；旧客户端先按 SemVer 升级到 beta.4，后续改按数字比较。

1. 提升 src/AdbDesk.App/AdbDesk.App.csproj 中 Version 和 VersionCode，完成构建、回归和便携版 publish。带测试版后缀的版本会发布为 Pre-release。
2. 用 PowerShell 7 执行：

   ```powershell
   ./scripts/package-release.ps1 -PublishDirectory ./dist/新版目录 -Version 1.0.0-beta.10
   ```

   ZIP 内直接包含程序文件，无外层目录。脚本生成 ZIP、SHA256SUMS.txt、update-manifest.json、update-manifest.sig、AdbDesk.version.json 五个附件。清单含所有文件的 SHA256，使用 RSA-PSS SHA256 签名；数字版本元数据必须一起上传。
3. 将已验证的源码推送到 GitHub main，并在对应源码树的提交上创建同名 v 版本标签，再推送标签。源码也同步到 Gitee；本地工具、构建产物、用户数据和私钥不进入源码提交。
4. 执行 `./scripts/publish-github-release.ps1 -Version 1.0.0-beta.10 -NotesFile ./docs/releases/v1.0.0-beta.10.md`。先上传草稿，核对远端所有附件的大小和 SHA256，成功后才公开。已公开版本不可覆盖，应递增版本发布。

发布签名私钥保存在发布电脑 `%LOCALAPPDATA%/AdbDesk/ReleaseKeys/update-private-key.dpapi`，仅当前 Windows 用户可解密。它不进入源码、安装目录或发行附件。请妥善备份发布密钥和 Windows 用户环境；丢失后不能通过重新生成不同密钥继续更新已有客户端。迁移发布机需要单独安排安全的密钥迁移。

## 失败处理

更新窗口中的“更新诊断”可展开错误详情、复制最近一次诊断和打开更新目录。最近错误保存为 Updates/last-update-diagnostic.txt；助手替换的完整事务日志与备份在该目录对应缓存子目录内。诊断不会自动上传。

更新异常堆栈的源码位置仅保留文件名和行号，例如 `UpdateService.cs:line 198`，不显示编译电脑的完整源码目录。界面、复制及新保存的诊断采用相同格式；复制旧版诊断时也会缩短其中的源码路径。异常类型、原因、方法调用及实际文件错误所涉及的路径仍保留。

beta.8 将发行列表及全部候选版本的元数据检查总时限从 15 秒调整为 60 秒。检查失败时显示正在读取的发行列表、清单、签名或数字版本附件，方便区分具体步骤；重试成功后旧异常折叠并标记为历史，保留原诊断文件。版本比较和签名验证规则保持不变。

- 下载或校验失败：当前程序不改变，可重新下载。
- 更新助手无法启动或无法就绪：保留正在运行的旧版。
- 替换文件前检查占用；不关闭其他程序使用的共享 ADB 服务。若其他 AdbDesk 或工具占用需要替换的文件，提示关闭占用后重试。
- 替换出错：按备份恢复已修改的文件。若恢复也失败，会保留日志、备份和缓存，提示人工恢复，不声称更新成功。
- 缓存及备份位于 `%LOCALAPPDATA%/AdbDesk/Updates`。确认新版本正常后，可在所有 AdbDesk 进程退出时手动清理旧的缓存子目录；不要删除个人设置或抓包恢复记录。

## 验证清单

测试包含 SemVer、发行版筛选、签名、下载哈希、取消、危险 ZIP 路径、文件占用及事务回滚。被智能应用控制拦截的环境只构建测试，不绕过系统策略执行。

在允许运行本程序的测试电脑上验证：从 beta.2 检查未来 beta.3；下载中取消；断网重试；正常替换后版本变更且历史/设置仍在；投屏和抓包关闭且代理恢复；故意占用需修改的文件时旧版保留；篡改清单/ZIP 时拒绝安装。没有发布更新版本时，「已是最新版本」是预期结果。
